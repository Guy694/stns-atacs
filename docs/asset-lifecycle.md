# วงจรชีวิตทรัพย์สิน: โอนย้าย ซ่อมบำรุง จำหน่ายแบบอนุมัติ และค่าเสื่อมราคา

เอกสารนี้อธิบายส่วนที่เพิ่มให้ “ทะเบียนทรัพย์สินและครุภัณฑ์” ครบวงจร โดยยังใช้ `information_assets` เป็นทะเบียนกลางและรักษา asset ID, URL, QR, survey/facility/work group และ Agent เดิมทั้งหมด

## สรุปสถาปัตยกรรม

| ส่วน | ที่เก็บข้อมูล | กติกาหลัก |
| --- | --- | --- |
| ประวัติโอนย้าย | `asset_transfers` (หนึ่งแถวต่อครั้ง) | เขียนทะเบียนกลาง ประวัติโอนย้าย และประวัติสถานะใน transaction เดียว ไม่เขียนทับ `usage_description` ต้องเลือกกลุ่มงานของหน่วยงานปลายทาง รายการที่ผูก Agent ย้ายหน่วยงานไม่ได้ |
| จำหน่าย / สูญหาย | `asset_disposal_requests` | ชำรุด/ระงับใช้งานมีผลทันที ส่วนจำหน่ายและสูญหายเป็น “คำขอ” จนกว่าผู้มีสิทธิ์ `disposal.approve` อนุมัติ ผู้เสนออนุมัติคำขอของตนเองไม่ได้ มีคำขอรออนุมัติได้ครั้งละหนึ่งรายการต่อทรัพย์สิน (ตรวจใน transaction ที่ล็อกแถวทรัพย์สิน) |
| งานซ่อมบำรุง | `asset_repairs`, `asset_repair_logs` | งานที่ยังไม่ปิดได้หนึ่งงานต่อทรัพย์สิน สถานะ รับแจ้ง → กำลังซ่อม/ส่งซ่อมภายนอก → ซ่อมเสร็จ/ยกเลิก ปิดงานแล้วเลือกสถานะทรัพย์สินได้ ทุกการเปลี่ยนสถานะอยู่ในไทม์ไลน์ |
| ค่าเสื่อมราคา | คำนวณจากข้อมูลเดิม + `information_assets.useful_life_years` (ไม่บังคับ) | เส้นตรง ราคาซาก 1 บาท ปีงบประมาณ ต.ค.–ก.ย. ปีเต็มคิดเท่ากัน ปีแรก/ปีสุดท้ายคิดตามจำนวนวัน อายุการใช้งานจากตารางใน `lib/asset-depreciation.ts` ตามประเภท/ประเภทย่อย หรือระบุรายรายการ |

สถานะ `Disposed` และ `Lost` เป็นสถานะปลายทาง: ตั้งได้จากการอนุมัติคำขอเท่านั้น ฟอร์มแก้ไข การนำเข้า CSV การตรวจนับ และรายงานจาก Agent เปลี่ยนกลับไม่ได้ ทรัพย์สินสถานะนี้โอนย้าย แจ้งซ่อม หรือเสนอจำหน่ายซ้ำไม่ได้ และไม่ถูกนับในมูลค่าทะเบียน เมื่ออนุมัติจำหน่าย งานซ่อมที่ค้างของรายการนั้นถูกยกเลิกอัตโนมัติพร้อมบันทึกในไทม์ไลน์

### บั๊กที่แก้พร้อมกัน

- การโอนย้ายและบันทึกชำรุด/จำหน่ายเดิมเขียนทับ “คำอธิบายการใช้งาน” ของทรัพย์สิน — ตอนนี้บันทึกลงประวัติแทน
- การโอนข้ามหน่วยงานเดิมคงกลุ่มงานของหน่วยงานต้นทางไว้ — ตอนนี้ต้องเลือกกลุ่มงานปลายทาง
- สถานะ `Disposed`/`Lost` ที่บันทึกจากหน้าตรวจนับเดิมถูกอ่านกลับเป็น “พร้อมใช้งาน” — ตอนนี้อ่านถูกต้อง และการตรวจนับบันทึกได้เฉพาะสภาพ (พร้อมใช้/ไม่ใช้งาน/ชำรุด) กรณีไม่พบมีลิงก์ “เสนอบันทึกสูญหาย”
- ฟอร์มจำหน่ายเดิมบันทึก “จำหน่ายออก” และ “สูญหาย” เป็น `Inactive` ทำให้แยกไม่ออก
- Dashboard สาธารณะนับรายการจำหน่าย/สูญหายเป็นใช้งานอยู่

## สิทธิ์ใหม่ (Permission Matrix)

| key | admin | officer | viewer |
| --- | --- | --- | --- |
| `disposal.approve` อนุมัติคำขอจำหน่าย/สูญหาย | ✓ | – | – |
| `repairs.view` ดูงานซ่อมบำรุง | ✓ | ✓ | ✓ |
| `repairs.manage` แจ้งซ่อมและปรับสถานะงานซ่อม | ✓ | ✓ | – |

ขอบเขตหน่วยงานใช้กติกาเดิม: officer ทำรายการได้เฉพาะหน่วยงานของตน (งานซ่อมรวมหน่วยงานที่ได้รับมอบหมายดูแล) ผู้ดูแลสามารถเปิดสิทธิ์อนุมัติให้ officer ได้ที่หน้า Permission Matrix โดยเมนู “จำหน่ายและเหตุผิดปกติ” ยังแสดงตามสิทธิ์ `disposal.manage`

## หน้าจอ

- `/repairs` รายการงานซ่อม สรุปปีงบประมาณ ค่าใช้จ่าย เวลาเฉลี่ย และทรัพย์สินที่ซ่อมบ่อย, `/repairs/new` แจ้งซ่อม, `/repairs/[id]` อัปเดตงานและไทม์ไลน์
- `/disposal` คำขอรออนุมัติ ผลการพิจารณา และค้นหาทรัพย์สินเพื่อบันทึก, `/disposal?requestId=` พิจารณา/ยกเลิกคำขอ
- `/transfer` เพิ่มวันที่โอน เลขที่หนังสือ กลุ่มงานปลายทาง และประวัติการโอนล่าสุด
- หน้ารายละเอียดทรัพย์สิน: มูลค่าและตารางค่าเสื่อมรายปีงบ, ประวัติโอนย้าย, ประวัติการซ่อม, คำขอจำหน่าย และปุ่มแจ้งซ่อม (สแกน QR แล้วแจ้งซ่อมได้ทันที)
- `/reports` เพิ่มแท็บ มูลค่าและค่าเสื่อมราคา / งานซ่อม / โอนย้าย / จำหน่าย-สูญหาย เลือกปีงบประมาณได้ และดาวน์โหลดทะเบียนค่าเสื่อมราคา CSV ที่ `/api/export/valuation?fy=2570`

## ค่าเสื่อมราคา

- ค่าเสื่อมต่อปี = (ราคาทุน − 1) ÷ อายุการใช้งาน, ค่าเสื่อมปีงบประมาณ = ค่าเสื่อมต่อปี × วันที่ถือครองในปีงบ ÷ จำนวนวันของปีงบ
- วันที่เริ่มคิด = วันที่ซื้อ/ได้รับมอบ ถ้าไม่มีใช้วันติดตั้ง
- ราคาต่ำกว่า 10,000 บาท แสดงในทะเบียนแต่ไม่คิดค่าเสื่อม (ปรับได้ที่ `CAPITALIZATION_THRESHOLD` ใน `lib/asset-valuation.ts`)
- ประเภทที่ตารางให้ “คณะกรรมการพิจารณาเป็นรายกรณี” (เช่น งานต่อเติม) หรือรายการที่กำหนดต่างจากตาราง ให้ระบุ “อายุการใช้งานสำหรับคิดค่าเสื่อม (ปี)” ในฟอร์ม หรือคอลัมน์ `useful_life_years` ใน CSV (ต่อท้ายคอลัมน์เดิม ไฟล์นำเข้ารุ่นเก่ายังใช้ได้)
- ตัวเลขเป็นการประมาณการเพื่อบริหารทรัพย์สินและวางแผนทดแทน ไม่ใช่การบันทึกบัญชีแยกประเภท ควรกระทบยอดกับระบบบัญชี (เช่น GFMIS) ก่อนใช้อ้างอิงทางบัญชี

## Migration และการนำขึ้นใช้งาน

ลำดับ: สำรองข้อมูล → migration แบบเพิ่มโครงสร้าง → ตรวจสอบ → deploy แอป → ทดสอบ workflow

```sh
# 1) สำรองข้อมูล (ตัวอย่าง Docker; เปลี่ยนชื่อ container ให้ตรง)
docker exec <mysql-container> sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines stn_atacs' > backup-before-lifecycle.sql

# 2) ตรวจ prerequisite แบบอ่านอย่างเดียว (อ่าน MYSQL_* จาก .env)
node scripts/migrate-asset-lifecycle.mjs

# 3) รัน migration และตรวจว่า ID/หน่วยงาน/สถานะ/กลุ่ม/ราคา/การผูก Agent ไม่เปลี่ยน
node scripts/migrate-asset-lifecycle.mjs --apply
```

`database/add_asset_lifecycle.sql` รันซ้ำได้ ไม่แก้หรือลบ table/column เดิม ไม่แก้แถวทรัพย์สิน ต้องการ MySQL 8.0.16+ (หรือ MariaDB 10.2+) สำหรับ CHECK constraint ข้อความ “Static analysis” ของ phpMyAdmin ที่ขึ้นที่ CHECK เป็นข้อจำกัดของตัวตรวจ syntax ของ phpMyAdmin ไม่ใช่ error จาก MySQL

ถ้าแอปใหม่ขึ้นก่อน migration หน้าเดิมทั้งหมดยังทำงาน ส่วนใหม่จะแสดงข้อความให้รัน migration และการบันทึกโอนย้าย/คำขอจำหน่าย/แจ้งซ่อมจะแจ้งข้อผิดพลาดแทนการบันทึกไม่ครบ

**Rollback แอป:** deploy แอปรุ่นก่อนหน้าได้ทันทีโดยคงตารางและข้อมูลใหม่ไว้ แอปรุ่นเก่าไม่อ่านตารางเหล่านี้ ห้าม DROP ตารางเพื่อย้อนกลับ เพราะจะทำให้ประวัติการโอน งานซ่อม และคำขอจำหน่ายที่ผู้ใช้บันทึกแล้วหายไป (MySQL DDL commit อัตโนมัติ ไม่ย้อนด้วย transaction) ข้อควรระวัง: แอปรุ่นเก่าอ่านสถานะ `Disposed`/`Lost` เป็น “พร้อมใช้งาน” จึงควร rollback เฉพาะกรณีจำเป็นและ deploy รุ่นใหม่กลับโดยเร็ว

## เลขครุภัณฑ์ รหัสสินทรัพย์ และคณะกรรมการตรวจนับ

Migration: `database/add_asset_codes_and_inspection_committee.sql` (เพิ่มอย่างเดียว รันซ้ำได้) — ต้องรันก่อน deploy แอปรุ่นนี้ เพราะการค้นหาทะเบียนอ่านคอลัมน์ใหม่

- **เลขครุภัณฑ์** = `asset_code_prefix` (รหัสหน่วยงาน เช่น สสจ.) + `asset_registration_no` (เลข เช่น 123) แสดงเป็น สสจ.123 ข้อมูลเดิมไม่ถูกแก้ ถ้าเลขเดิมมีรหัสนำหน้าอยู่แล้วจะไม่แสดงซ้ำ กติกาเลขซ้ำยังตรวจที่ `asset_registration_no` เหมือนเดิม
- **รหัสหน่วยงานเริ่มต้น** ตั้งที่ ตั้งค่าระบบ → หน่วยงาน (`health_facilities.asset_code_prefix`) ฟอร์มเพิ่มครุภัณฑ์เติมให้อัตโนมัติ แก้รายรายการได้
- **รหัสสินทรัพย์** (`asset_accounting_code`) เช่น เลขสินทรัพย์ GFMIS ถ้าว่างและราคาต่ำกว่า 10,000 บาท ใบตรวจนับพิมพ์ “ต่ำกว่าเกณฑ์”
- **รอบตรวจนับตามกลุ่มงาน** (`asset_inspections.work_group_id`) เลือกกลุ่มงานตอนเปิดรอบ รายการที่จำหน่าย/สูญหายแล้วไม่ถูกนำเข้ารอบใหม่
- **คณะกรรมการ** (`asset_inspection_committee`) ประธาน 1 + กรรมการ 3 กำหนดตอนเปิดรอบหรือแก้ไขในหน้ารอบตรวจ
- **ใบตรวจนับ Excel** แยกชีตตามประเภทครุภัณฑ์ มีหัวกระดาษ (ชื่อรอบ หน่วยงาน กลุ่มงาน) แถบประเภท หัวตาราง ตัวกรอง เส้นตาราง แถวรวม และช่องลงนามคณะกรรมการ 4 คน ตั้งค่าพิมพ์ A4 แนวนอนพอดีความกว้าง หัวตารางพิมพ์ซ้ำทุกหน้า (เขียนด้วย `lib/xlsx-writer.ts` เพราะ SheetJS รุ่น community เขียนรูปแบบเซลล์ไม่ได้)

## ตรวจนับประจำปี: ปิดรอบ รายงานผล สแกน QR และเสนอจำหน่ายจากผลตรวจ

Migration: `database/add_inspection_close.sql` (เพิ่ม `asset_inspections.round_status`, `closed_at`, `closed_by` รันซ้ำได้) — ก่อนรัน หน้ารอบตรวจยังใช้ได้ แต่ปุ่มปิดรอบจะแจ้งให้รัน migration

- **ปิดรอบ / เปิดรอบใหม่** ผู้มีสิทธิ์ตรวจนับปิดรอบได้จากหน้ารอบตรวจ หากยังมีรายการไม่ได้ตรวจต้องยืนยันก่อน เมื่อปิดแล้วแก้ผลตรวจ คณะกรรมการ และลบรอบไม่ได้ (ตรวจฝั่ง server) บันทึกผู้ปิดและเวลาใน audit log
- **รายงานผลการตรวจสอบพัสดุประจำปี** (`/api/export/inspection/{id}?type=report`) ชีตสรุปจำนวนและมูลค่าตามประเภท แยก ใช้งานได้ / ชำรุด / เสื่อมสภาพ-ไม่ใช้งาน / ไม่พบ / ยังไม่ได้ตรวจ พร้อมข้อความรายงานและลงนามคณะกรรมการ และชีตรายการชำรุด-ไม่พบ หากรอบยังไม่ปิดจะพิมพ์คำว่า “ฉบับร่าง”
- **สแกน QR** ในหน้ารอบตรวจ ใช้กล้องมือถือ (เบราว์เซอร์ที่รองรับ BarcodeDetector) หรือแอปกล้องสแกน QR บนตัวครุภัณฑ์ หน้าครุภัณฑ์จะแสดงปุ่ม “พบ – ใช้งานได้ / ชำรุด / ไม่ใช้งาน” ของรอบที่เปิดอยู่ กดครั้งเดียวบันทึกผล ค้นหาด้วยเลขครุภัณฑ์หรือชื่อได้เช่นกัน
- **เสนอจำหน่ายหลายรายการ** จากรายการชำรุด/เสื่อมสภาพ (คำขอจำหน่าย) และไม่พบ (คำขอสูญหาย) ในรอบตรวจ ต้องมีสิทธิ์ `disposal.manage` ระบบอ่านผลตรวจซ้ำฝั่ง server ข้ามรายการที่มีคำขอรออนุมัติอยู่แล้วหรือจำหน่ายไปแล้ว คำขอทุกรายการยังต้องผ่านขั้นอนุมัติตามปกติ

## ติดตามงาน ความครบถ้วนของข้อมูล การจำหน่ายจริง และยืม-คืน

Migration: `database/add_registry_completeness.sql` (เพิ่มคอลัมน์ที่เป็น NULL ได้และตาราง `asset_loans` เท่านั้น รันซ้ำได้) — ก่อนรัน หน้าเดิมยังใช้ได้ ส่วนใหม่จะแจ้งให้รัน migration หรือข้ามหัวข้อที่ยังไม่มีคอลัมน์

ลำดับการรันทั้งหมด (ข้ามไฟล์ที่เคยรันแล้วได้): `add_asset_lifecycle.sql` → `add_asset_codes_and_inspection_committee.sql` → `add_inspection_close.sql` → `add_registry_completeness.sql` สำรองฐานข้อมูลก่อน และเปิดดูว่าไฟล์สำรองมีข้อมูลจริง (ไม่ใช่ 0 ไบต์)

### ภาพรวมและการตรวจนับ
- **ความคืบหน้าการตรวจนับประจำปี** บน dashboard: ต่อหน่วยงาน นับครุภัณฑ์ที่ยังอยู่ในทะเบียน เทียบกับรอบที่เริ่มในปีงบประมาณ (ใช้ตัวกรองปีงบประมาณของ dashboard ถ้าไม่เลือกใช้ปีปัจจุบัน) แสดง ตรวจแล้ว / อยู่ในรอบแต่ยังไม่ตรวจ / ยังไม่อยู่ในรอบใด และสถานะ ยังไม่เปิดรอบ · กำลังตรวจ · ตรวจครบรอปิดรอบ · ปิดรอบแล้วแต่ตกหล่น · ปิดรอบครบ
- **หน้าความครอบคลุม** `/inspection/coverage` รายการครุภัณฑ์ที่ยังไม่อยู่ในรอบใดของปี กรองตามอำเภอ/หน่วยงาน
- **กำหนดส่งรายงาน** = วันเริ่มตรวจ + 30 วันทำการ (นับเฉพาะจันทร์–ศุกร์ ไม่รวมวันหยุดราชการ) แสดงในรายการรอบ หน้ารอบ และงานรอดำเนินการ (ใกล้ครบกำหนด ≤ 7 วัน)
- **เลขที่/วันที่คำสั่งแต่งตั้งคณะกรรมการ** (`asset_inspections.committee_order_no/date`) บันทึกในส่วนคณะกรรมการ และพิมพ์ในรายงานผลการตรวจสอบ
- **งานรอดำเนินการ** บน dashboard: คำขอรออนุมัติ, อนุมัติแล้วรอบันทึกผลการจำหน่าย, งานซ่อมค้าง (เร่งด่วน/สูง), รอบตรวจนับเปิดอยู่ (เกิน/ใกล้กำหนด), การยืมที่ยังไม่คืน (เกินกำหนด)

### ทะเบียนและความครบถ้วน
- **ข้อมูลการได้มา** ใน `information_assets`: `funding_source` (Budget, Maintenance, Fund, Donation, Other), `acquisition_method` (EBidding, EMarket, Selection, Specific, Donation, Transfer, Other), `vendor_name`, `warranty_end_date`, `unit_name` — มีในฟอร์ม หน้ารายละเอียด และคอลัมน์ท้ายไฟล์นำเข้า/ส่งออก CSV (นำเข้ารับทั้งรหัสและชื่อภาษาไทย)
- **ความครบถ้วนของข้อมูล** `/data-quality`: คะแนน = ช่องที่กรอกแล้ว / ช่องที่ต้องมี ของหัวข้อ เลขครุภัณฑ์ มูลค่า วันที่ได้มา กลุ่มงาน ที่ตั้ง รหัสสินทรัพย์ (เฉพาะราคา ≥ 10,000 บาท) แหล่งเงิน วิธีได้มา — เลือกหัวข้อเพื่อดูรายการที่ขาด และรายการ Serial Number ซ้ำ (ไม่นับค่าอย่าง "-", "N/A") หน้าครุภัณฑ์เตือนเมื่อ Serial ซ้ำกับรายการอื่น
- **ทะเบียนคุมทรัพย์สิน** `/print/assets/{id}`: รายละเอียด ค่าเสื่อมราคารายปี และประวัติโอนย้าย ซ่อม ยืม-คืน ตรวจนับ จำหน่าย พิมพ์ A4 หรือบันทึก PDF

### การจำหน่าย
- **ผลการสอบหาข้อเท็จจริง** (`fact_finding_note`) กรอกตอนเสนอบันทึกสูญหาย ก่อน migration จะต่อท้ายเหตุผลแทน
- **บันทึกผลการจำหน่าย** หลังอนุมัติ (`executed_on`, `execution_document_no`, `execution_note`, `proceeds_amount`, ผู้บันทึก) แก้ไขภายหลังได้ ทุกครั้งบันทึกในประวัติสถานะและ audit log ช่องเงินที่ได้รับย้ายจากขั้นอนุมัติมาไว้ขั้นนี้
- **เอกสาร Excel** `/api/export/disposal?type=pending` รายการขออนุมัติจำหน่าย และ `?type=annual&fy=2570` รายงานการจำหน่ายประจำปี (อนุมัติในปีงบประมาณ) พร้อมยอดรวมและช่องลงนาม

### ยืม-คืน (`asset_loans`, เมนู `/loans`)
- สิทธิ์ใหม่ `loans.view` (ค่าเริ่มต้น: ทุกบทบาท) และ `loans.manage` (Admin, Officer) ปรับได้ใน Permission Matrix
- ยืมได้ครั้งละ 1 รายการต่อครุภัณฑ์ (ตรวจภายใต้ row lock), ห้ามยืมรายการชำรุด/จำหน่าย/สูญหาย, ระยะยืมไม่เกิน 1 ปี, การยืมไม่เปลี่ยนหน่วยงานเจ้าของ
- รับคืนสภาพชำรุด → เปลี่ยนสถานะครุภัณฑ์เป็นชำรุด ทุกการยืม/คืน/ยกเลิกบันทึกประวัติสถานะและ audit log

### แจ้งเตือน Telegram
หมวดใหม่ `lifecycle`: คำขอจำหน่าย/สูญหายใหม่ (รวมคำขอจากผลตรวจเป็นข้อความเดียว), ผลการพิจารณา, แจ้งซ่อมใหม่ ปิดเฉพาะหมวดนี้ได้ด้วย `TELEGRAM_ALERT_LIFECYCLE=false`

## ตรวจนับด้วย QR: กลุ่มงานที่พบ

Migration: `database/add_inspection_found_location.sql` (เพิ่ม `asset_inspection_items.found_work_group_id`, `found_location`, `registered_work_group_id` รันซ้ำได้) — ก่อนรัน ผลตรวจยังบันทึกได้ตามปกติ แต่ไม่เก็บกลุ่มงานที่พบ

- สแกน QR บนสติกเกอร์ต้องเข้าสู่ระบบก่อน (`/scan/assets/{id}` พาไปหน้าเข้าสู่ระบบแล้วกลับมาที่ครุภัณฑ์) ส่วนกล้องในหน้ารอบตรวจใช้ได้เฉพาะผู้ที่เข้าสู่ระบบแล้ว
- แผงตรวจนับในหน้าครุภัณฑ์แสดง **หน่วยงานและกลุ่มงานตามทะเบียนก่อน** แล้วให้เลือก "พบที่กลุ่มงาน" (ค่าเริ่มต้นตามทะเบียน) และกรอกที่ตั้งที่พบถ้าต่างจากเดิม ตารางในหน้ารอบตรวจก็เลือกกลุ่มงานที่พบได้
- ระบบเก็บกลุ่มงานในทะเบียน ณ เวลาที่ตรวจไว้ด้วย รายงานจึงยังแสดงที่เดิมได้แม้ทะเบียนถูกปรับภายหลัง
- ติ๊ก "ปรับกลุ่มงาน/ที่ตั้งในทะเบียนเป็นที่พบ" เพื่อย้ายในทะเบียนทันที (บันทึกประวัติสถานะและ audit log) ถ้าไม่ติ๊ก จะรายงานความต่างไว้เท่านั้น
- รายงานผลการตรวจสอบมีแผ่นงาน **"พบต่างสถานที่"** (ทะเบียน → พบที่) และข้อสังเกตจำนวนรายการในชีตสรุป ใบตรวจนับและชีตรายการชำรุดแสดง "พบที่: ..." ใต้กลุ่มงานเดิม

ไม่มี migration ใหม่ในรอบนี้

- **สติ๊กเกอร์ QR เป็นชุด** `/print/stickers?facility=ID[&workGroup=ID]` หรือ `?ids=1,2,3` (`lib/sticker-sheet.ts`): ขนาด `mini` 30×15 มม. 108 ดวง (ตัดตามเส้น), `s65` 38.1×21.2, `s40` 45.7×25.4, `s21` 63.5×38.1 (ตรงกับกระดาษสติ๊กเกอร์ A4 ตัดสำเร็จ) · เว้นดวงที่ใช้แล้ว (`skip`), จำนวนชุด (`copies`), ปรับตำแหน่งเครื่องพิมพ์ (`dx`/`dy` มม.), กรอบทดลองพิมพ์ (`outline=1`) · QR ใช้ลิงก์สั้น `/q/{id}` (ขนาดจิ๋วเข้ารหัสเป็นตัวพิมพ์ใหญ่ `/Q/{id}` ให้ QR เล็กลงหนึ่งรุ่น แล้ว rewrite ใน `next.config.ts`) ไป `/scan/assets/{id}` ที่ต้องล็อกอิน
- **ตรวจนับออฟไลน์** (`scan-check-in.tsx`, `lib/offline-inspection.ts`): โหมดสแกนต่อเนื่องบันทึก “พบ” ลง localStorage ต่อรอบ แล้วส่ง `POST /api/inspection/{id}/results` (ครั้งละไม่เกิน 100 รายการ) เมื่อออนไลน์ / ทุก 20 วินาที / กดส่ง · ทุกรายการผ่าน `recordInspectionResult` (`lib/inspection-results.ts`) ชุดเดียวกับฟอร์ม: รอบต้องเปิด ครุภัณฑ์ไม่จำหน่าย/สูญหาย สิทธิ์หน่วยงาน กลุ่มงานของหน่วยงาน · ข้อจำกัด: ต้องเปิดหน้ารอบไว้ก่อนขาดสัญญาณ, การสแกนในหน้าใช้ BarcodeDetector (Chrome/Android) — Safari ใช้การค้นหาแทน
- **สรุป Telegram รายวัน** `GET /api/cron/daily-summary` (Bearer `CRON_SECRET`, `?dry=1` ดูข้อมูลโดยไม่ส่ง) ส่งวันละ 1 ข้อความ (event key `daily-summary:YYYY-MM-DD`)
- **แผนทดแทน** รายงาน → แผนทดแทน และ `/api/export/replacement` (Excel): คะแนน ชำรุด 3, ตัดค่าเสื่อมครบ/เกินอายุ 2, ซ่อม ≥ 3 ครั้งใน 2 ปี 2, ค่าซ่อมสะสม ≥ 50% ราคาทุน 2, ไม่ใช้งาน 1 → ≥5 เร่งด่วน, ≥3 ควรวางแผน, อื่น ๆ เฝ้าระวัง (`lib/replacement-plan.ts`)
- **รูปครุภัณฑ์ต้องล็อกอิน**: เก็บที่ `UPLOAD_DIR` (ค่าเริ่มต้น `storage/uploads`) เสิร์ฟผ่าน `app/uploads/assets/[file]` ตรวจสิทธิ์หน่วยงานของครุภัณฑ์เจ้าของรูป URL ในฐานข้อมูลคงเดิม `/uploads/assets/...` รูปเก่าใน `public/uploads` ยังอ่านได้ ย้ายด้วย `scripts/move-legacy-uploads.mjs`
