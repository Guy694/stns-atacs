## ต้องทำบน server / GitHub (ทำในโค้ดไม่ได้)

- [ ] **เปลี่ยนรหัสผ่านบัญชีจากไฟล์ seed** — ประวัติ git ยังมี `database/seed_users.sql` ซึ่งมีรหัสผ่าน plaintext ใน comment
      ใช้ `database/check_seed_accounts.sql` หาบัญชีที่ยังใช้รหัสเดิม ถ้า repo เคยเป็น public ให้ถือว่ารหัสรั่วแล้ว
      (ถ้าต้องการลบออกจากประวัติ: `git filter-repo` แล้ว force push — ต้องแจ้งทุกคนที่ clone ไว้)
- [ ] **ตั้งระบบสำรองข้อมูล** ทั้งฐานข้อมูล MySQL และโฟลเดอร์ `storage/uploads`
      (ภาพทรัพย์สิน + ภาพประกาศ `storage/uploads/announcements`) แล้วลองกู้คืนจริงอย่างน้อยหนึ่งครั้ง
- [ ] **ตั้งค่า env บน server**
  - [ ] `TRUSTED_PROXY_COUNT` (จำนวน proxy หน้าแอป เช่น nginx = 1) — ไม่ตั้งแล้ว rate limit / log จะเห็น IP ผิด
  - [ ] `CRON_SECRET` — ไม่ตั้งแล้วงานตั้งเวลาทั้งหมด (สรุปรายวัน, ตรวจ backup, ตรวจ Agent) จะถูกปฏิเสธ
- [ ] **รัน migration ที่ค้าง** (สำรองฐานข้อมูลก่อนทุกครั้ง)
  - [ ] `database/add_thaid_link_approval.sql`
  - [ ] `database/add_security_events.sql`
  - [ ] `database/add_app_settings.sql`
- [ ] **รัน `npm audit --omit=dev`** ในเครื่องที่ต่ออินเทอร์เน็ตได้ แล้วจัดการรายการระดับ high/critical

## ต้องตรวจหลัง build Docker ครั้งถัดไป

- [ ] รัน `database/add_agent_health.sql` (สำรองฐานข้อมูลก่อน) — ก่อนรัน Agent ส่งข้อมูลได้ แต่ไม่บันทึกส่วนสุขภาพเครื่อง
- [ ] ติดตั้ง **Agent 2.0.0** ทับบนเครื่อง Windows 1–2 เครื่องก่อน แล้วตรวจที่เมนู "สุขภาพเครื่องคอมพิวเตอร์":
      ไม่เกิดเครื่องซ้ำ, มีไดรฟ์ C: รายตัว, สถานะ Activate / แอนตี้ไวรัส / อัปเดตล่าสุดตรงกับเครื่องจริง
      และ `C:\ProgramData\ATACSAgent` ผู้ใช้ทั่วไปเปิดไม่ได้ (สคริปต์ PowerShell ยังไม่ได้ทดสอบบน Windows จริง)
- [ ] ติดตั้ง Agent 2.0.0 บนเครื่อง Linux 1 เครื่อง (ทดสอบบน Ubuntu VM แล้ว)

- [ ] นำเข้าไฟล์ **.xlsx** หนึ่งไฟล์ — ถ้าขึ้น "ไม่สามารถอ่านไฟล์ CSV หรือ Excel ได้" แปลว่า worker
      (`scripts/parse-spreadsheet-worker.mjs`) หรือ `node_modules/xlsx` ไม่ติดไปใน image
      ตรวจ `outputFileTracingIncludes` ใน `next.config.ts` (CSV ไม่ได้รับผลกระทบ)
- [ ] นำเข้าไฟล์ **CSV UTF-8 จาก Excel** ที่มีวันที่ `YYYY-MM-DD` — ควรผ่านแล้ว (เดิมพังทั้งหัวคอลัมน์และวันที่)
- [ ] ทดสอบออกจากระบบ — ต้องไปหน้า login ทันที และกด Back แล้วไม่เห็นข้อมูลเดิม

## งานโค้ดที่รอทำเมื่อมีโอกาส

- [ ] **อัปเดต `xlsx` เป็น 0.20.3** จาก `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz`
      (บน npm ไม่มีเวอร์ชันที่แก้ CVE-2023-30533 / CVE-2024-22363) — ตอนนี้ลดความเสี่ยงไว้แล้วด้วยการอ่าน Excel
      ใน worker thread ที่จำกัดเวลา/หน่วยความจำ และอ่าน CSV ด้วยตัวอ่านของระบบเอง อัปเดตแล้วโค้ดใช้ต่อได้ทันที

- [ ] รัน integration test กับฐานข้อมูลทดสอบ (ไม่ใช่ production) และเปิดดู UI ในเบราว์เซอร์จริง
- [ ] เพิ่มหัวข้อ "ประกาศ popup" และ "ออกจากระบบ" ในคู่มือในระบบ (`lib/user-manual.ts`)

## ข้อที่ยังเปิดอยู่จากรายงาน ก.ย. 2569 (`docs/security-review-2026-09.md`)

เรียงตามที่ควรทำก่อน รายละเอียดและแนวทางแก้อยู่ในรายงานฉบับนั้น

- [ ] SEC-13 งานซ่อม/ยืม/ผลตรวจนับยังยึดหน่วยงานเดิมหลังโอนย้าย (หน่วยงานเดิมแก้ครุภัณฑ์ที่โอนไปแล้วได้)
- [ ] SEC-10 Google ผูกบัญชีด้วยอีเมลที่ยังไม่ยืนยัน
- [ ] SEC-17 ไฟล์สำรองข้อมูลไม่เข้ารหัสและสิทธิ์ไฟล์ 0644 — ทำพร้อมกับการตั้งระบบ backup
- [ ] SEC-35 Caddy ค่าเริ่มต้นเป็น HTTP (`SITE_ADDRESS=:80`)
- [ ] SEC-14, SEC-15 (ส่วนผูกอัตโนมัติ), SEC-16, SEC-33 กลุ่ม Agent (ลงทะเบียนซ้ำแย่ง key, ตรวจข้อมูลรายงาน, Telegram ท่วม, audit log)
- [ ] SEC-19 สคริปต์ Agent ตรวจความถูกต้องของไฟล์ที่ดาวน์โหลด (SEC-18 แก้ใน Agent 2.0 แล้ว รอทดสอบบน Windows จริง)
- [ ] SEC-20 เพิ่ม PKCE/nonce ใน OAuth (ThaiD, Google)
- [ ] SEC-23 หน้าดาวน์โหลด Agent และ API บางตัวไม่ตรวจ Permission Matrix
- [ ] ระดับต่ำที่เหลือ: SEC-24, SEC-26 – SEC-31, SEC-34, SEC-36 – SEC-38

## ทำเสร็จแล้วในรอบนี้ (ยังไม่ commit)

- อ่าน Excel ใน worker thread แยก + ตัวอ่าน CSV ของระบบเอง (`lib/spreadsheet-parse.ts`, `lib/csv-parse.ts`)
- cron เทียบ `CRON_SECRET` แบบเวลาคงที่ (`lib/cron-auth.ts`) = SEC-25
- ออกจากระบบแล้วไปหน้า login ทันที
- Agent 2.0.0 (Windows/Linux) + ตรวจข้อมูลฝั่งเซิร์ฟเวอร์ (SEC-32, SEC-15 บางส่วน) + หน้า `/agent-monitor`
- ประกาศ popup (ตั้งค่าที่ `/admin/settings/announcement`) และเวอร์ชัน `v.1.0.0` ใน footer
